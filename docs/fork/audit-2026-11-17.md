# Fork audit — 2026-11-17

A whole-fork review ahead of a public release: every commit between upstream
`adfc5021` (0.4.2, the merge base) and `a13f2f45` — 102 fork commits, 12 from
upstream's Silero VAD branch and 25 merges, about 79 k lines outside `ggml/`
and `vendor/`. This file records the scope, what was found and fixed, what was
checked and left alone, and how the fork now compares with upstream.

## Scope and method

The review went in order of real-time impact:

1. The stream dispatcher and the audio front end (fast path, Earshot, speech
   gate, RNNoise).
2. The GPU decode paths (Parakeet device decoder, `causal_lm::StepPipeline`)
   and the CPU threadpools.
3. The public C ABI additions, then the Rust bindings and build script, then
   the plugin loader.
4. The docs.

Three kinds of code were not read line by line: bundled weights (`*.inl`),
vendored code (cJSON, dr_wav, miniz), and model-port internals already gated
by byte-identical transcript A/Bs in their own commits.

Baseline at `a13f2f45`: `ctest` 72/72 (one model-gated skip), `cargo test`
80/80, clang-format clean, teardown lint clean.

## Checked, no change needed

- **Parakeet GPU decoder.** It is per session (no sharing between concurrent
  sessions). Pinned staging is ordered on one stream. Confidence logits are
  read before the next copy can overwrite them. A device failure trims the
  partial tokens and decodes on the CPU from the same LSTM state. Capacity
  grows geometrically and is trimmed above 2048 frames on scratch release.
- **`StepPipeline`.** It launches only steps the plain loop's budget allows.
  Token, position, KV row, mask and bias live outside the scheduler's allocator,
  so the set-once clobbering hazard (`55504bde`) cannot occur. A pinned slot is
  reused only after its event. The one step launched past EOS writes a KV row
  that the next prefill overwrites. The commit's own A/B covered this: R2T2
  streaming 24/24 identical.
- **Threadpools.** OpenMP is off, so each CPU backend keeps one persistent ggml
  pool. Re-applying it per compute costs a mutex and a map lookup. Idle
  sessions park it, so a Multi-STT host's idle models do not spin.
- **Stream timeline.** Skipped gaps are recorded and mapped back for Parakeet
  token times and for the cursors. Moonshine-streaming and Voxtral-realtime
  keep committed behind input after their first audio, so they only ever skip
  leading silence. That is correct; it is also a possible future saving.
- **Speech gate, RNNoise wrapper, Earshot wrapper.** Ring buffer and pre-roll
  never release a frame twice. `in == out` aliasing is safe. Every C entry
  point catches its allocations.
- **Rust wrappers.** Handles are `Send` but not `Sync`. Gate audio borrows the
  gate across a `&mut` call. `from_raw_parts` is null- and length-guarded.
- **Hot loops.** Environment variables are read at graph build, never per
  decode step. The conformer flash-probe cache is mutex-guarded.
- `src/transcribe-chunking.*` is unwired on purpose (master plan B.4) and stays.

## Fork vs upstream

Measured on an RTX 4070 Laptop GPU (CUDA 13, sm_89) and an i9-13900H, on an
idle machine with none of the reviewer's own jobs running. The upstream arm is
`adfc5021` built with its own defaults (`TRANSCRIBE_CUDA=ON`, graphs off,
`GGML_NATIVE=ON`); the fork arm is this audit's tree.

Method: one CLI process per measurement, run twice (`-r 2`), timed on the
second run (the library's `mel + encode + decode`). 4 interleaved rounds with
alternating start; round 1 dropped; mean of 3. Granite and the Qwen3 CPU case
are timed by wall clock instead, as `(wall(-r 5) - wall(-r 1)) / 4`, because
upstream's Granite `decode=` leaves out the token loop (it reports 171 ms for a
411 ms run).

## Effect of this audit's fixes on transcripts

Only streaming can change (offline paths and static builds are untouched).
`a13f2f45` and this tree were compared on Nemotron 3.5 streaming (CPU, 160 ms
chunks), each with one chunk per feed and with 480 ms feeds:

- `jfk`, `jobs-silence`, `german`, `dots`, `whole-earth`: 10/10
  byte-identical.
- `jfk` and `jobs-silence` attenuated to -30 dB and -36 dB: 8/8
  byte-identical. They also match a run with the fast path disabled
  (`TRANSCRIBE_DISABLE_ACTIVITY_GATE=1`). What changes at -36 dB
  ("American") comes from the quiet input, not the gate.

So the window fix moved no transcript on real audio. It closes the worst case
the new unit test constructs: a short, quiet onset at the end of a large feed
while Earshot has not yet flipped.

ZER0 is unaffected either way. Since its `a12ca902`, ZER0 gates capture with
`transcribe_vad_gate_*` and opens every stream with `enable_vad = false`, so
the stream fast path serves other hosts. The gate itself is untouched by this
audit.

## Open items

- **Binary packaging lanes.** The Python wheels (`bindings/python-native-*`)
  and the Swift xcframework (`scripts/ci/package_xcframework.sh`) still bundle
  only the ggml / miniz / Silero texts. The `cmake --install` tree has all of
  them; if this fork ever publishes those artifacts, add `LICENSE.earshot` and
  `LICENSE.rnnoise` at least.
- **Downstream docs** that describe the old plugin search order (model folder
  first) need the new order and `TRANSCRIBE_ARCH_SEARCH_MODEL_DIR`. They are
  inert while no consumer builds `arch-dl`.
- **Streaming benchmarks** are cold-stream only, because the CLI refuses
  `--repeat` with `--stream-chunk-ms`. A repeat for streams would give
  steady-state numbers.
- **Earshot AVX-512** is designed to match the baseline/AVX2 scores but was
  not tested on this machine.
